# Documentation process (shared)

Shared instructions for AgentFleet project agents and Doc Bot. Project-specific
details live in each repo's `AGENT-DOCS.md` (see the template in the aflt
package). This file is **opt-in**: aflt delivers its path on launch/resume when
`.agentfleet.json` has `"agentDocs": true`.

## Goals

- Keep a short, factual trail of where the work is and what is next.
- Prefer dated evidence over optimistic copy.
- Never invent progress. Elapsed time is not progress.

## Where docs live

| Location | Role |
|---|---|
| Project `AGENTS.md` | Existing project instructions — **preserve**; do not replace |
| Project `AGENT-DOCS.md` | Project-specific documentation pointers (paths, cadence) |
| Memory `<project>/dashboard.md` | Human / Doc Bot summary |
| Memory `<project>/status-notes/*.md` | Dated evidence (newest live filename = latest) |
| Memory `<project>/status-notes/archive/` | Addressed / obsolete notes — **ignore** when finding "latest" |
| Memory `<project>/_aflt/` | Generated by `aflt memory sync` — never hand-edit |
| Memory root `DASHBOARD.md` | Generated Active/Dormant table + Doc Bot summary block |

When no memory repo is configured, still follow project `AGENTS.md` /
`AGENT-DOCS.md`. Report the missing memory config clearly; do not invent a
memory path.

## Status notes

- Write a **new** file under `status-notes/` after a milestone or substantial session.
- Filename: `YYYY-MM-DDTHHMM-<kebab-slug>.md` (local time). Never overwrite an old note.
- Latest = lexicographic max of live `*.md` filenames. Do **not** read `archive/` for pickup.
- Archive convention: humans/Doc Bot may **move** (not delete) obsolete notes into
  `status-notes/archive/`, keeping the original filename. **aflt never auto-moves or deletes documents.**

## Checkpoints

Opt-in projects may record documentation checkpoints via aflt:

```bash
aflt docs checkpoint request   # bookkeeping: update requested
aflt docs checkpoint complete  # bookkeeping: update completed (optional --note PATH)
aflt docs --status             # shows open / overdue checkpoints
```

- **Requested / completed** are the only progress signals.
- **Overdue** means a requested checkpoint has no matching completion past the
  configured threshold — for status/dashboard only. Do not treat age as progress.
- Never interrupt a busy agent to demand a docs update. Reminders belong in
  status / dashboard (Doc Bot inbox notes via opted-in messaging — issue #2).

## Doc Bot

`aflt memory doc` runs the portable documentarian (`DOC-AGENT.md` in the memory
repo). Agents should leave a clear status note when a checkpoint completes so
Doc Bot can summarize later. When messaging is enabled on both the requester
and `doc-bot`, checkpoints may drop a note in the Doc Bot inbox (context only;
never wakes a busy agent). Doc Bot should poll `aflt inbox` when idle and mark
handled items complete.

## Don'ts

- Do not overwrite `AGENTS.md` or replace existing project instructions.
- Do not edit `_aflt/` or the generated Active/Dormant tables by hand.
- Do not auto-move or delete status notes (or any docs) from aflt itself.
- Do not paste secrets, tokens, or `.env` contents into notes or dashboards.
- Do not commit, push, stash, reset, or delete files unless the user asked.
