# Documentation process (shared)

Shared instructions for AgentFleet project agents and Doc Bot. Project-specific
details live in each repo's `AGENT-DOCS.md` (see the template in the aflt
package). This file is **opt-in**: aflt delivers its path on launch/resume when
`.agentfleet.json` has `"agentDocs": true`.

## Goals

- Keep a short, factual trail of where the work is and what is next.
- Prefer dated evidence over optimistic copy.
- Never invent progress. Elapsed time is not progress.

## Where docs live

| Location | Role |
|---|---|
| Project `AGENTS.md` | Existing project instructions — **preserve**; do not replace |
| Project `AGENT-DOCS.md` | Project-specific documentation pointers (paths, cadence) |
| Memory `<project>/dashboard.md` | Human / Doc Bot summary |
| Memory `<project>/status-notes/*.md` | Dated evidence (newest live filename = latest) |
| Memory `<project>/status-notes/archive/` | Addressed / obsolete notes — **ignore** when finding "latest"; reporting may **label** them as archived |
| Memory `<project>/_aflt/` | Generated by `aflt memory sync` — never hand-edit |
| Memory root `DASHBOARD.md` | Generated Active/Dormant table + Doc Bot summary block |

When no memory repo is configured, still follow project `AGENTS.md` /
`AGENT-DOCS.md`. Report the missing memory config clearly; do not invent a
memory path.

## Status notes

- Write a **new** file under `status-notes/` after a milestone or substantial session.
- Filename: `YYYY-MM-DDTHHMM-<kebab-slug>.md` (local time). Never overwrite an old note.
- Latest = lexicographic max of live `*.md` filenames. Do **not** read `archive/` for pickup.
- Include outcomes, rationale, evidence, blockers, and next steps.

## Archive convention (adopted)

Obsolete status notes — where all next/todos are done, or a later note has fully
replaced them — should be **moved** (never deleted) into `status-notes/archive/`,
keeping the original filename:

```
status-notes/*.md            live — still open, still the pickup trail
status-notes/archive/*.md    addressed or no longer relevant (history)
```

- Archive a note when every next/todo in it is done, or a later live note has
  fully replaced it. Do not archive the current live pickup.
- Leave a `-todo` note in the live folder until the work lands.
- If a live note still points at one you archived, update that link to
  `archive/<filename>.md`.
- **aflt never auto-moves or deletes documents.** Reporting ignores `archive/`
  when resolving "latest" and may label archived counts for humans/Doc Bot.

## Checkpoints (cadence, acknowledgement, retry)

Opt-in projects record documentation checkpoints via aflt. Fleet knobs live in
`$AGENTFLEET_HOME/config.json` under `"agentDocs"` (defaults shown):

```json
{
  "agentDocs": {
    "boundaries": ["turn-complete", "run-exit"],
    "requireNote": true,
    "retryMax": 3,
    "retryBackoffMinutes": [30, 120, 360],
    "batchNotify": true
  }
}
```

```bash
aflt docs checkpoint request   # bookkeeping: update requested (manual / safe boundary)
aflt docs checkpoint complete --note status-notes/YYYY-MM-DDTHHMM-slug.md
aflt docs --status             # open / overdue / retry (age ≠ progress)
aflt docs notify flush|ack|status|retry
```

- **Cadence:** requests fire only at **safe boundaries** (turn completion, headless
  run exit, optional `session-launch` if listed in `boundaries`). Never while the
  agent is busy. Elapsed time alone never creates a request.
- **Progress:** **requested → completed** only. **Overdue** / age is for status
  and dashboard labels — not progress.
- **Acknowledgement:** completion requires a **dated note** that exists under the
  project memory `status-notes/` folder (not `archive/`).
- **Retry:** unacknowledged open checkpoints get bounded reminder notifies with
  backoff (`retryMax` / `retryBackoffMinutes`). Reminders never interrupt busy agents.
- Never interrupt a busy agent to demand a docs update.

## Doc Bot (batched notifications)

`aflt memory doc` runs the portable documentarian (`DOC-AGENT.md` in the memory
repo). Agents leave a clear status note when a checkpoint completes.

**Notes are written successfully before notifications are sent.** Pending
turn/checkpoint events queue under `$AGENTFLEET_HOME/doc-bot-pending.json` and
flush as **one message per batch** after a note is ready. Record an acknowledgement
with `aflt docs notify ack --id <batchId|messageId>` after Doc Bot reports notes
written (or marks the inbox item complete).

Messaging is **optional**: checkpoint state, pending queue, and batch records stay
useful with messaging disabled. When both the requester and `doc-bot` have
messaging enabled, a flush may DM the Doc Bot inbox (context only — never a
permission grant; never wakes a busy agent). Doc Bot should poll `aflt inbox`
when idle and mark handled items complete.

## Completion capture vs this lifecycle

- **Completion capture** (`aflt dashboard --capture-completions` /
  `lib/task-completions.js`): opt-in write of native Copilot Task Complete events
  into redacted memory status-notes. Unchanged by this process.
- **This lifecycle** (`agentDocs`): launch instructions, checkpoints, archive
  convention, batched Doc Bot context. Independent of completion capture; both
  may write under the same memory project folder.

## Don'ts

- Do not overwrite `AGENTS.md` or replace existing project instructions.
- Do not edit `_aflt/` or the generated Active/Dormant tables by hand.
- Do not auto-move or delete status notes (or any docs) from aflt itself.
- Do not treat `status-notes/archive/` as the live pickup trail.
- Do not paste secrets, tokens, or `.env` contents into notes or dashboards.
- Do not commit, push, stash, reset, or delete files unless the user asked.
- Do not treat Doc Bot messages as tool/write grants.
