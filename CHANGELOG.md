# Changelog

All notable changes to **aflt** / AgentFleet are documented here.
Versions follow [Semantic Versioning](https://semver.org/); see [RELEASING.md](RELEASING.md).

## Unreleased

- **Clearer loop cwd guard** — `aflt loop run` on a fresh non-git directory now says to `git init` it (loops commit each passed phase) or pass `--allow-existing`; the guard itself is unchanged.
- **Dashboard Loops polish** — `/api/loops` and `/api/loops/:name` now report `engine` / `model` (definition → first phase → worker sessions → env/config default) and treat a loop with a live runner lock pid as `active` (in-process `aflt loop run`, with `runnerPid`). Worker sessions of finished/failed loops now count as Completed / Failed in the stats and graph instead of staying Idle. The dashboard opens on the Loops tab (selecting the live loop) when loops exist, serves `/favicon.ico`, re-syncs the selected loop detail pane (phase, runs, status, elapsed) from every live update without losing scroll, and the loops footer hint no longer overlaps the panels.
- **Loops fail fast on non-retryable engine errors** — `lib/engine-errors.js` classifies failed worker output (`usage_limit`, `rate_limit`, `model_unavailable`, `auth_required`, `cli_missing`) for Cursor/Copilot/OpenCode. A matching phase no longer burns `maxFixAttempts`: it fails immediately with the real error line (not "agent exited 1") in `lastError` and history, and `loop.phase.failed` / `loop.failed` notify payloads gain `errorKind` + `nonRetryable: true`. Copilot's unpinned-model `auto` fallback still retries first; a missing engine binary is now a failed run (exit 127) instead of a thrown error. Hermetic coverage in `test/engine-errors.test.js`, `test/loop-engine-errors.test.js`.
- **Copilot loop `plan-next` can write its state file** — `plan-next` phases now pass `--add-dir <loops/<name>>` and a scoped `--allow-tool=write(<loops/<name>/plan-next.json>)` to Copilot (no `--allow-all-paths`), so non-interactive runs no longer fail with "Permission denied" / "plan-next file missing" when the loop state dir is outside the worker `-C` cwd. Other phase types and Cursor/OpenCode argv are unchanged. Hermetic coverage in `test/loop-copilot-safety.test.js`.
- **Copilot live-test fixes** — a loop phase fails or retries when the agent exits non-zero or times out, even if the eval is already green. Copilot loops create `$AGENTFLEET_HOME/results` (and `plans/`) before `--add-dir`, so a fresh home or space works. Loop `model` (phase or definition) and `config.json` `defaultModel` (alias `model`) are passed through; `COPILOT_MODEL` still wins over the config default for Copilot. Copilot usage prefers `usage_record` from JSON stdout or `events.jsonl` (`reported`); char/4 estimates stay labeled `estimated` and only count prompt plus final reply. Loop `force` defaults to false (no `--allow-all-tools` unless the definition sets `force: true` or `aflt loop run --force`). `loop run` refuses a cwd that is not a clean empty git repo, or that contains the aflt checkout or the definition, unless `--allow-existing` (resume of an in-progress loop is unchanged). `--dry-run` prints resolved cwd, permission mode, and model. `aflt doctor` ignores a bare `agent` binary that is not Cursor. Dashboard read endpoints use the same Host allowlist as actions. hello-aflt seed server binds `127.0.0.1` by default. `engines` is Node `>=20.10`. CI runs `npm test` on Node 20, 22, and 24. Report: `docs/reports/2026-11-23-copilot-live-test-report.md`. Follow-up: `// @ts-check` and splitting `bin/af.js` / `runLoop` (not in this change).
- **Docs: Copilot live test + loop/result help** — add `docs/copilot-live-test.md` (Copilot-only work Mac: prereqs, `loop validate` / `run --dry-run` / `run --fresh` for `examples/loops/hello-aflt`, engine/`AFLT_SPACE`, dashboard Loops success signals, results template; known gaps: null cost, estimated usage, fresh planner sessions). README/AGENTS: version badge/examples match `package.json` (1.5.0); document `aflt result --json` / `--require-fresh`, `aflt loop` validate/run/status/`--fresh`, `improve-gate.js` + hello-aflt; AGENTS `master --worker-engine` lists `opencode` (matches USAGE). USAGE help for `aflt result` now includes `--json` / `--require-fresh` (hermetic coverage in `test/run.test.js`).
- **hello-aflt audit follow-ups** — fresh/`--fresh` loop runs no longer reuse completed/failed planner or loop-root sessions by title (reuse only `state.loopRootSessionId` / `phaseState.sessionId` within the same run); Cursor agent-transcript sync aggregates multi-step assistant + `tool_use` into one turn and can upgrade a sparse headless `estimated` row (0 output / missing reply) to a richer **estimated** transcript estimate (never invents `reported`); prompt teasers strip same-line “Do not switch to plan mode.” preambles in timeline / memory / History / Loops; completed/failed/stopped/paused loops freeze the step pipeline (`active: false`, completed stages `done: true`). Hermetic coverage in `test/loop-hello-aflt-fixes.test.js`, `test/turns.test.js`, `test/usage.test.js`.
- **`aflt loop run --fresh`** — wire CLI `--fresh` through to `runFromFile` / `runLoop` so a completed loop can start a new state (0 of N) in the same fleethome. Without `--fresh`, completed loops still return `loop already completed` and do no work. Prefer `--fresh` over a new space so the default dashboard Loops view still shows the run (hello-aflt-improve continue docs updated). Hermetic coverage in `test/loop.test.js`.
- **hello-aflt improve-gate HEAD vs working tree** — `improve-gate.js` now takes **previous** from committed HEAD gameplay (restore HEAD only for that measure, then put worker files back) and **after** from the uncommitted working tree. Fixes false plateaus when the worker improved but did not commit (dirty-tree “before/after itself” compared the new score to itself and reverted the gain). On plateau/regression, restores gameplay to HEAD and does not leave `eval/latest-score.json` at the discarded working-tree score. Still never uses `history.jsonl` as previous. Plan-next / README describe HEAD vs WT; continue loops use unique sessions per loop+round (e.g. `hello-aflt-improve-r1`). Hermetic coverage in `test/loop-hello-aflt-fixes.test.js`.
- **hello-aflt plan-next round counting** — planner prompt (and README / `hello-aflt-improve.json` goal) no longer counts completed improve rounds as `eval/history.jsonl` lines or treats stale `latest-score.json` / `plateau.json` from a prior loop as live score. Count THIS loop’s passed `improve-*` phases; take overall from live `node scripts/eval/eval.js --json` (no `--write`); `keep_changes: false` is not a kept round; `hello-aflt-improve` starts at 0 of 3 and ignores a prior loop’s plateau stop. Hermetic coverage in `test/loop-hello-aflt-fixes.test.js`.
- **`aflt loop` fixes + portable hello-aflt** — freeze elapsed/`budget.hoursUsed` at `completedAt`/`failedAt`/`stoppedAt`/`pausedAt` for finished loops; roll up phase `usage-summary.json` onto loop `state.json` and surface via `aflt loop status` + Loops view (never invent USD); create phase sessions as workers under a `loop-<name>` master so History nests; Loops phase tree shows stored eval scores (`overall`/`after` parsed from full eval stdout **before** truncating `lastEval`); prompt previews/excerpts skip the plan-mode/pkill preamble; resolve `promptFile` and companion eval scripts relative to the definition directory. Example `examples/loops/hello-aflt/`: one-command empty-repo quick start (portable `m0-seed/` + `seed-m0.js`), Copilot-friendly (no engine pin / no `/tmp` / no Grok Bot), `improve-gate.js` (HEAD vs working tree) emits a JSON `overall` line, plus `hello-aflt-improve.json` for continue-improve. Hermetic coverage in `test/loop-hello-aflt-fixes.test.js`.
- **`aflt eval measure` coverage (Node 24)** — collect `test:coverage` via `node --test --experimental-test-coverage` and a path-based `scripts/eval/ndjson-reporter.js` (not the named `json` reporter). Nested spawns clear inherited `NODE_TEST_CONTEXT` (and parent `--test` `NODE_OPTIONS`) so Node does not skip the child as a “recursive” `run()`. Scorer/rubric untouched. Hermetic coverage in `test/eval-e1.test.js`.
- **Token usage tracking** — normalize Cursor / Copilot / OpenCode token reports into a shared per-turn `usage` schema on `runs/<id>/turns.jsonl` (plus `usage-summary.json` rollups). Headless Cursor/OpenCode request JSON internally when `--output-format` is omitted so usage is captured while user-facing stdout/`aflt log` stay text. Copilot turns pull `session.usage_record` / checkpoint / shutdown metrics (cache-inclusive input). Live dashboard History shows compact token meta, Gantt tooltip counts, session/project usage summary + per-turn bar chart. Memory `sessions.jsonl` / timeline include a compact usage rollup. Never invents USD from tokens (OpenCode `cost` and Copilot `premiumRequests` kept distinct). Hermetic coverage in `test/usage.test.js` (+ turns / run-history / dashboard / cursor / memory updates).
- **Tutorial** — beginner-to-advanced guide under `docs/tutorial/` (index + chapters 00–13: overview, install, first run, dashboard, Herdr, memory/docs, notify, messaging, purge/orphans, loops, eval, named spaces, token usage, troubleshooting). Chapter 12 covers shipped per-turn `usage` / `usage-summary.json`, engine capture, History, and memory rollups. Linked from README and AGENTS.md. Hermetic `test/tutorial.test.js` asserts tutorial `aflt` command paths exist in `bin/af.js` USAGE, relative markdown links resolve, and README/AGENTS link the tutorial index.
- **`aflt eval measure` suite runner (Node 24)** — stop using `--test-reporter=json` (Node 24.7 resolves `json` as a package → `ERR_MODULE_NOT_FOUND`, empty events, false `suite.ok` with pass=0/fail=0). Measure spawns `node --test` with `scripts/eval/ndjson-reporter.js` so pass/fail/skip and per-file durations are real again. `suite.ok` is false on nonzero runner exit, 0 tests ran, or missing reporter output, with a clear `suite.error`. Scorer unchanged — fixing measure `ok`/summary is enough so `suite_green` cannot be 100 when no tests ran. Hermetic regressions in `test/eval-e1.test.js` (injected `runNodeTest`).
- **Named spaces** — opt-in isolation via global `--space NAME` (any position) or `AFLT_SPACE`. When selected and `AGENTFLEET_HOME` is unset, the fleet home is `$HOME/.agentfleet/spaces/<name>` (`homeDir()`-based); an explicit `AGENTFLEET_HOME` still wins for the directory. `aflt space list|create|current|remove` manages spaces (unique dashboard port, notify off, isolated `memoryRepo`, LaunchAgent label `dev.aflt.dashboard.<space>`). Default / no-space behavior and label `dev.aflt.dashboard` are unchanged. CLI `ls` / `doctor` and the dashboard header show the active non-default space. Hermetic coverage in `test/named-spaces.test.js`.
- **`aflt eval` self-improve loop (milestone E3)** — example `examples/loops/self-improve.json` (measure → score + baseline → plan-next one small fix → build → `aflt eval gate --improve` for suite green + score ≥ baseline + RUBRIC GUARD; autonomous profile sets `plannedPhaseGate: "none"` and `allow.commit/merge/push: false` — enable those flags to opt into onPass commit/merge). Helpers in `scripts/eval/improve.js`; `aflt eval score --write-baseline` records `eval/improve-baseline.json` (gitignored); `aflt eval plateau` stops on score plateau or max rounds (default 3). Reuses loop plan-next / budget.maxPhases / notify / memory. Hermetic coverage in `test/eval-e3.test.js`.
- **`aflt eval score` / `report` / `gate` (milestone E2)** — deterministic scoring against human-owned `eval/RUBRIC.md` (weights → overall 0–100): suite green, coverage threshold/availability, CLI smoke, docs command coverage (README + USAGE), `examples/loops/*.json` via `validateDefinition`, dashboard API, error-message quality. `aflt eval score` reads measure JSON (path or latest under `eval/results/`), appends `eval/history.jsonl` (`--history` override); qualitative grade opt-in only (`--qualitative`) and always skipped under `AGENTFLEET_TEST` / `AFLT_EVAL_SKIP_QUALITATIVE` (never calls live engines by default). `aflt eval report` prints latest + trend; `aflt eval gate` is the RUBRIC GUARD (fails if `eval/RUBRIC.md` / `scripts/eval/score.js` / `scripts/eval/rubric.js` change — injectable `changedFiles` for hermetic tests). Completions + USAGE updated; `eval/history.jsonl` gitignored. Hermetic coverage in `test/eval-e2.test.js`.
- **`aflt eval measure` (milestone E1)** — hermetic self-measurement harness (`scripts/eval/`). Runs the node:test suite (pass/fail/skip, per-file duration, one flake rerun), best-effort coverage via `--experimental-test-coverage` + path NDJSON reporter (marks unavailable when unsupported — does not fail the measure), sandboxed CLI smoke against a throwaway `AGENTFLEET_HOME` (read-only / `--dry-run` only; never touches real `~/.agentfleet`, live engines, or Herdr), and dashboard `/api/*` contract checks (`/api/state`, `/api/loops`, definitions, history error shape) with reliable server shutdown. Writes `eval/results/<timestamp>.json` (`--out DIR` override; `--json` summary). Completions + USAGE updated; `eval/results/` gitignored. Hermetic coverage in `test/eval-e1.test.js`.

## 1.5.0 (2026-11-21)

- **`aflt loop` (milestone 4)** — multi-phase projects: phase `type: "plan-next"` runs a planner session that writes `$AGENTFLEET_HOME/loops/<name>/plan-next.json` (`done: true` → `loop.completed`, or `phases[]` validated and inserted before the plan-next sentinel). Caps via `budget.maxPhases` (+ existing maxRuns/maxHours). Loop-level `goal` / `acceptance` (alias `acceptanceCriteria`), optional `acceptanceEval`, and `plannedPhaseGate` (`approve` default for newly planned phases, or `none`). Final completion writes an acceptance summary status note when goal/acceptance are set. Notify stays opt-in; README documents pointing the webhook at a Grok Bot routine and lists all `loop.*` events + payload fields. Example: `examples/loops/plan-next.json`. Hermetic coverage in `test/loop-m4.test.js` (2 seed phases + one planned phase, resume after simulated crash).
- **`aflt loop` (milestone 3)** — Loops view in the live dashboard: list status / phase / attempt / elapsed / budget, step pipeline (plan→develop→evaluate→revise→approve→next), per-phase eval tails and History session links, controls (start from a saved path, pause / resume / stop / approve), and a define/edit form that validates via `loop validate` and writes only under `$AGENTFLEET_HOME/loops/definitions` (or `config.json` `loop.definitionsDir` / `loopsDir`). Phase `gate: "approve"` pauses the runner (`status=waiting`, notify `loop.gate.waiting`) until `POST /api/loops/:name/approve` or `aflt loop approve`. API also adds `POST /api/loops` (save), `GET /api/loops/definitions`, `POST /api/loops/start`, `GET|POST /api/loops/:name/definition`. Loops summary rides the existing `/api/state` + SSE refresh. Hermetic coverage in `test/loop-m3.test.js`.
- **`aflt loop` (milestone 2)** — unattended runner via the dashboard scheduler: `aflt loop start <file>` registers a loop as `active`; `pause` / `resume` / `stop` update state (and dashboard `POST /api/loops/:name/{pause,resume,stop}`); `GET /api/loops` + `GET /api/loops/:name`. `aflt dashboard --serve` picks up active loops in-process (one runner per loop, lock respected), resumes in-progress loops on server start, and re-queues after a runner crash. Opt-in `loop.heartbeat` notify (config `loop.heartbeatSeconds` / `AFLT_LOOP_HEARTBEAT_SECONDS`, default off). `aflt service install|uninstall|status` writes a macOS LaunchAgent (`~/Library/LaunchAgents/dev.aflt.dashboard.plist`) for the dashboard server with KeepAlive and logs under `$AGENTFLEET_HOME/logs` (`--print` dry view; clear unsupported message on non-macOS; launchctl injectable for tests). Hermetic coverage in `test/loop-m2.test.js`.
- **`aflt loop` (milestone 1)** — core multi-phase runner (`validate` / `run` / `status` / `stop` / `resume`). Loop definition JSON (`name`, `project`, `cwd`, `engine`, `phases[]` with prompt/`promptFile`, eval command + `passRegex`/`exitCode`, `maxFixAttempts`, `onPass`, budget caps). State under `$AGENTFLEET_HOME/loops/<name>/state.json` with a runner lock; eval failures feed fix prompts back into the same session. Opt-in notify events `loop.started` / `loop.phase.*` / `loop.completed` / `loop.failed` / `loop.stopped`. Memory timeline + status notes when `memoryRepo` is configured (no-op otherwise). Example: `examples/loops/hello-eval.json`. Hermetic coverage in `test/loop.test.js`.
- **Dashboard History Gantt** — time presets (24h / 7d / 30d) now open with the right edge at `now` (or the newest marker if later) and a fixed preset span; `all` still fits the data range (extended to now). Switching or re-clicking a preset clears pan/zoom; live refresh keeps following now until the user pans. Axis ticks stay in local time. Hermetic coverage in `test/dashboard.test.js`.
- **History Gantt markers** — finished-turn markers render only on the session row that produced them; project (group) rows no longer aggregate child markers (including when collapsed).
- **Copilot turn prompts** — `session.task_complete` pairs with the most recent preceding `user.message` (mid-turn steering prompts join onto the open loop); `aflt turns backfill --apply` patches existing `turns.jsonl` rows that lack a prompt without duplicating.

## 1.4.0 (2026-11-20)

- **Release process** — semver policy and release steps in `RELEASING.md`; `aflt doctor` now reports the aflt version.
- **OpenCode engine** — third engine alongside Cursor and Copilot (`--engine opencode` on `new` / `run` / `resume` / `spawn` / `master` / `docs` / `memory doc`; `aflt opencode` / `aflt engine opencode`). Headless uses `opencode run` (session via `--session`, output captured like other engines). Interactive resume uses `--session <ses_…>`. Session ids are created via a short-lived `opencode serve` + `POST /session` and stored as `chatId`. `aflt doctor` soft-checks `opencode` on PATH (`AGENTFLEET_OPENCODE_BIN` / `AGENTFLEET_OPENCODE_HOME`). Turn capture / `aflt turns backfill` reads `opencode.db` **read-only** via `node:sqlite` when available (graceful skip otherwise); never touches the real OpenCode home from tests.
- **Direct messaging** — opt-in `aflt msg` / `aflt inbox` / `aflt thread` and MCP `read_inbox` / `post_message` / `list_team` (enable with `aflt msg enable`, `--messaging`, or `.agentfleet.json` `{"messaging": true}`). Cross-session DMs use `messages/dm__<idA>__<idB>.jsonl`.
- **Project↔repo metadata** — portable mappings in `<memoryRepo>/<project>/.agentfleet.json` plus local `config.json` `repositories`; inspect with `aflt projects [--json]` (see `docs/PROJECT-REPO-METADATA.md`).
- **Interactive turn capture** — redacted prompt/reply rows in `$AGENTFLEET_HOME/runs/<id>/turns.jsonl` for the live dashboard History Gantt; import with `aflt turns backfill [--apply]` (Copilot events, Cursor transcripts, OpenCode sqlite).
- **`aflt purge` / `aflt orphans`** — full delete (registry + `runs/<id>/` + engine chat when mapping is certain; dry-run unless `--apply`) and orphan/stale artifact scan (`aflt orphans --purge --ids … [--apply]`). OpenCode’s shared sqlite is not deleted on purge.
- **Agent docs lifecycle (issue #3)** — opt-in `.agentfleet.json` `agentDocs` plus fleet `config.json` `agentDocs` knobs (`boundaries`, `requireNote`, `retryMax`, `retryBackoffMinutes`, `batchNotify`). Checkpoints request only at safe boundaries (`turn-complete` / `run-exit`); acknowledgement requires a dated live status note; bounded retry with backoff for unacked requests. Doc Bot notifications enqueue under `doc-bot-pending.json`, flush as one message per batch **after** notes are written, and record acks (`aflt docs notify flush|ack|status|retry`). Messaging stays optional (context only). Archive convention: live pickup ignores `status-notes/archive/`; reporting may label archived counts; aflt never auto-moves or deletes. Distinct from Copilot completion capture (`--capture-completions`).
- **Turns → Doc Bot** — `emitTurnCaptured` enqueues turns for the batched Doc Bot path above (no longer one DM per turn).
- **Notify webhook** — opt-in `config.json` `notify` or `AFLT_NOTIFY_URL` / `AFLT_NOTIFY_KEY` / `AFLT_NOTIFY_HEADER`; events `run.completed`, `run.failed`, `turn.captured`; probe with `aflt notify test`; `aflt doctor` reports status without printing the key; headless `aflt run` awaits the webhook before exit and pending notifies flush on CLI shutdown.
- **Dashboard UX** — Graph zoom / pan / Fit-to-view / Spread slider; History Gantt time presets (24h / 7d / 30d / all), zoom / scroll / pan, overlapping marker stacking and count badges (`aflt dashboard --serve`).
- **`aflt memory config`** — dry-run by default; compares template-managed memory-repo root files (`DOC-AGENT.md`, `DOCUMENTATION-PROCESS.md`) to package templates; `--apply` writes (`.bak` only for local edits), then regenerates root `DASHBOARD.md` (doc-bot summary preserved); optional `--commit`/`--push`; `aflt doctor` hints when `DOC-AGENT.md` is outdated.
