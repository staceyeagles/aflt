# Changelog

All notable changes to **aflt** / AgentFleet are documented here.
Versions follow [Semantic Versioning](https://semver.org/); see [RELEASING.md](RELEASING.md).

## Unreleased

- **`aflt eval score` / `report` / `gate` (milestone E2)** — deterministic scoring against human-owned `eval/RUBRIC.md` (weights → overall 0–100): suite green, coverage threshold/availability, CLI smoke, docs command coverage (README + USAGE), `examples/loops/*.json` via `validateDefinition`, dashboard API, error-message quality. `aflt eval score` reads measure JSON (path or latest under `eval/results/`), appends `eval/history.jsonl` (`--history` override); qualitative grade opt-in only (`--qualitative`) and always skipped under `AGENTFLEET_TEST` / `AFLT_EVAL_SKIP_QUALITATIVE` (never calls live engines by default). `aflt eval report` prints latest + trend; `aflt eval gate` is the RUBRIC GUARD (fails if `eval/RUBRIC.md` / `scripts/eval/score.js` / `scripts/eval/rubric.js` change — injectable `changedFiles` for hermetic tests). Completions + USAGE updated; `eval/history.jsonl` gitignored. Hermetic coverage in `test/eval-e2.test.js`.
- **`aflt eval measure` (milestone E1)** — hermetic self-measurement harness (`scripts/eval/`). Runs the node:test suite (pass/fail/skip, per-file duration, one flake rerun), best-effort coverage via `node --experimental-test-coverage` (marks unavailable when unsupported — does not fail the measure), sandboxed CLI smoke against a throwaway `AGENTFLEET_HOME` (read-only / `--dry-run` only; never touches real `~/.agentfleet`, live engines, or Herdr), and dashboard `/api/*` contract checks (`/api/state`, `/api/loops`, definitions, history error shape) with reliable server shutdown. Writes `eval/results/<timestamp>.json` (`--out DIR` override; `--json` summary). Completions + USAGE updated; `eval/results/` gitignored. Hermetic coverage in `test/eval-e1.test.js`.

## 1.5.0 (2026-11-21)

- **`aflt loop` (milestone 4)** — multi-phase projects: phase `type: "plan-next"` runs a planner session that writes `$AGENTFLEET_HOME/loops/<name>/plan-next.json` (`done: true` → `loop.completed`, or `phases[]` validated and inserted before the plan-next sentinel). Caps via `budget.maxPhases` (+ existing maxRuns/maxHours). Loop-level `goal` / `acceptance` (alias `acceptanceCriteria`), optional `acceptanceEval`, and `plannedPhaseGate` (`approve` default for newly planned phases, or `none`). Final completion writes an acceptance summary status note when goal/acceptance are set. Notify stays opt-in; README documents pointing the webhook at a Grok Bot routine and lists all `loop.*` events + payload fields. Example: `examples/loops/plan-next.json`. Hermetic coverage in `test/loop-m4.test.js` (2 seed phases + one planned phase, resume after simulated crash).
- **`aflt loop` (milestone 3)** — Loops view in the live dashboard: list status / phase / attempt / elapsed / budget, step pipeline (plan→develop→evaluate→revise→approve→next), per-phase eval tails and History session links, controls (start from a saved path, pause / resume / stop / approve), and a define/edit form that validates via `loop validate` and writes only under `$AGENTFLEET_HOME/loops/definitions` (or `config.json` `loop.definitionsDir` / `loopsDir`). Phase `gate: "approve"` pauses the runner (`status=waiting`, notify `loop.gate.waiting`) until `POST /api/loops/:name/approve` or `aflt loop approve`. API also adds `POST /api/loops` (save), `GET /api/loops/definitions`, `POST /api/loops/start`, `GET|POST /api/loops/:name/definition`. Loops summary rides the existing `/api/state` + SSE refresh. Hermetic coverage in `test/loop-m3.test.js`.
- **`aflt loop` (milestone 2)** — unattended runner via the dashboard scheduler: `aflt loop start <file>` registers a loop as `active`; `pause` / `resume` / `stop` update state (and dashboard `POST /api/loops/:name/{pause,resume,stop}`); `GET /api/loops` + `GET /api/loops/:name`. `aflt dashboard --serve` picks up active loops in-process (one runner per loop, lock respected), resumes in-progress loops on server start, and re-queues after a runner crash. Opt-in `loop.heartbeat` notify (config `loop.heartbeatSeconds` / `AFLT_LOOP_HEARTBEAT_SECONDS`, default off). `aflt service install|uninstall|status` writes a macOS LaunchAgent (`~/Library/LaunchAgents/dev.aflt.dashboard.plist`) for the dashboard server with KeepAlive and logs under `$AGENTFLEET_HOME/logs` (`--print` dry view; clear unsupported message on non-macOS; launchctl injectable for tests). Hermetic coverage in `test/loop-m2.test.js`.
- **`aflt loop` (milestone 1)** — core multi-phase runner (`validate` / `run` / `status` / `stop` / `resume`). Loop definition JSON (`name`, `project`, `cwd`, `engine`, `phases[]` with prompt/`promptFile`, eval command + `passRegex`/`exitCode`, `maxFixAttempts`, `onPass`, budget caps). State under `$AGENTFLEET_HOME/loops/<name>/state.json` with a runner lock; eval failures feed fix prompts back into the same session. Opt-in notify events `loop.started` / `loop.phase.*` / `loop.completed` / `loop.failed` / `loop.stopped`. Memory timeline + status notes when `memoryRepo` is configured (no-op otherwise). Example: `examples/loops/hello-eval.json`. Hermetic coverage in `test/loop.test.js`.
- **Dashboard History Gantt** — time presets (24h / 7d / 30d) now open with the right edge at `now` (or the newest marker if later) and a fixed preset span; `all` still fits the data range (extended to now). Switching or re-clicking a preset clears pan/zoom; live refresh keeps following now until the user pans. Axis ticks stay in local time. Hermetic coverage in `test/dashboard.test.js`.
- **History Gantt markers** — finished-turn markers render only on the session row that produced them; project (group) rows no longer aggregate child markers (including when collapsed).
- **Copilot turn prompts** — `session.task_complete` pairs with the most recent preceding `user.message` (mid-turn steering prompts join onto the open loop); `aflt turns backfill --apply` patches existing `turns.jsonl` rows that lack a prompt without duplicating.

## 1.4.0 (2026-11-20)

- **Release process** — semver policy and release steps in `RELEASING.md`; `aflt doctor` now reports the aflt version.
- **OpenCode engine** — third engine alongside Cursor and Copilot (`--engine opencode` on `new` / `run` / `resume` / `spawn` / `master` / `docs` / `memory doc`; `aflt opencode` / `aflt engine opencode`). Headless uses `opencode run` (session via `--session`, output captured like other engines). Interactive resume uses `--session <ses_…>`. Session ids are created via a short-lived `opencode serve` + `POST /session` and stored as `chatId`. `aflt doctor` soft-checks `opencode` on PATH (`AGENTFLEET_OPENCODE_BIN` / `AGENTFLEET_OPENCODE_HOME`). Turn capture / `aflt turns backfill` reads `opencode.db` **read-only** via `node:sqlite` when available (graceful skip otherwise); never touches the real OpenCode home from tests.
- **Direct messaging** — opt-in `aflt msg` / `aflt inbox` / `aflt thread` and MCP `read_inbox` / `post_message` / `list_team` (enable with `aflt msg enable`, `--messaging`, or `.agentfleet.json` `{"messaging": true}`). Cross-session DMs use `messages/dm__<idA>__<idB>.jsonl`.
- **Project↔repo metadata** — portable mappings in `<memoryRepo>/<project>/.agentfleet.json` plus local `config.json` `repositories`; inspect with `aflt projects [--json]` (see `docs/PROJECT-REPO-METADATA.md`).
- **Interactive turn capture** — redacted prompt/reply rows in `$AGENTFLEET_HOME/runs/<id>/turns.jsonl` for the live dashboard History Gantt; import with `aflt turns backfill [--apply]` (Copilot events, Cursor transcripts, OpenCode sqlite).
- **`aflt purge` / `aflt orphans`** — full delete (registry + `runs/<id>/` + engine chat when mapping is certain; dry-run unless `--apply`) and orphan/stale artifact scan (`aflt orphans --purge --ids … [--apply]`). OpenCode’s shared sqlite is not deleted on purge.
- **Agent docs lifecycle (issue #3)** — opt-in `.agentfleet.json` `agentDocs` plus fleet `config.json` `agentDocs` knobs (`boundaries`, `requireNote`, `retryMax`, `retryBackoffMinutes`, `batchNotify`). Checkpoints request only at safe boundaries (`turn-complete` / `run-exit`); acknowledgement requires a dated live status note; bounded retry with backoff for unacked requests. Doc Bot notifications enqueue under `doc-bot-pending.json`, flush as one message per batch **after** notes are written, and record acks (`aflt docs notify flush|ack|status|retry`). Messaging stays optional (context only). Archive convention: live pickup ignores `status-notes/archive/`; reporting may label archived counts; aflt never auto-moves or deletes. Distinct from Copilot completion capture (`--capture-completions`).
- **Turns → Doc Bot** — `emitTurnCaptured` enqueues turns for the batched Doc Bot path above (no longer one DM per turn).
- **Notify webhook** — opt-in `config.json` `notify` or `AFLT_NOTIFY_URL` / `AFLT_NOTIFY_KEY` / `AFLT_NOTIFY_HEADER`; events `run.completed`, `run.failed`, `turn.captured`; probe with `aflt notify test`; `aflt doctor` reports status without printing the key; headless `aflt run` awaits the webhook before exit and pending notifies flush on CLI shutdown.
- **Dashboard UX** — Graph zoom / pan / Fit-to-view / Spread slider; History Gantt time presets (24h / 7d / 30d / all), zoom / scroll / pan, overlapping marker stacking and count badges (`aflt dashboard --serve`).
- **`aflt memory config`** — dry-run by default; compares template-managed memory-repo root files (`DOC-AGENT.md`, `DOCUMENTATION-PROCESS.md`) to package templates; `--apply` writes (`.bak` only for local edits), then regenerates root `DASHBOARD.md` (doc-bot summary preserved); optional `--commit`/`--push`; `aflt doctor` hints when `DOC-AGENT.md` is outdated.
